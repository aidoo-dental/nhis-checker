# Подписване и публикуване

[← Начална страница](../README.md)


За Mac `scripts/notarize-macos.py` взема готов DMG, подписва включените библиотеки и приложението, изпраща приложението и новия DMG за нотариализация и прикрепя двата билета. Преди приключване проверява подписите, съдържанието на DMG и Gatekeeper. Ключовете остават в Keychain; скриптът приема името на идентичността и на локалния notary профил като аргументи.

За Windows `scripts/azure-pipelines-signing.yml` използва съществуващата Azure service connection. В защитения Azure Repos клон добави прегледан `signing-approval.json` с `runId`, `artifactId`, `commit`, `digest` (във формат `sha256:…`) и `version`. Pipeline проверява тези стойности през GitHub API и сверява изтегления архив преди подписването. Приема само успешен push build на `main` от Windows workflow на това хранилище.

За въвеждане в Azure осигури GitHub credential с право **Actions: read** за хранилището чрез секретната променлива `nhisGithubReadToken`, без override при стартиране. Премахни стария `nhisPayloadUrl` и ограничи подписващата service connection до защитената дефиниция и одобрения ref. Само упълномощени лица трябва да могат да променят одобрението и YAML файла. Провери, че старите refs не могат да използват подписващата връзка.

След проверка на архива Azure подписва основния EXE, деинсталатора и крайния инсталатор с времеви печат. Проверяват се подписите, инсталирането, интерфейсът и деинсталирането. `node --test tests/verify-windows-payload.mjs` проверява отказ при различно хранилище, неуспешен билд, различен run и неподходящ digest.

Приложението, инсталаторите и GitHub release трябва да имат една и съща версия. Източникът на версията е `project(... VERSION ...)` в `CMakeLists.txt`. Публично се публикуват само файловете, преминали проверките за подпис и пакетиране.
